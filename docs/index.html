Can snapshot signals prioritize a content review queue?

An honest evaluation of a transparent rule and logistic-regression triage model on anonymized production-search data.

Abstract

This project asks whether observed search, freshness, and engagement signals can prioritize content pages for human review. I evaluated a transparent rule baseline and logistic-regression model using 30,000 pseudonymized content items from the FlyRank ML Internship starter dataset. On a holdout of eight unseen pseudonymized clients, the model reached precision@20 of 0.850 versus 0.700 for the baseline, with average precision of 0.600 and ROC AUC of 0.589 against a 0.517 proxy-label base rate. The model is therefore a modestly better triage signal, not a reliable prediction of future performance or of the result of an edit. The output is a capped, reason-coded queue for a human reviewer to investigate before making any content decision.

Introduction / problem statement

Editorial attention is scarce: which content items should a reviewer investigate first? The unit of analysis is one pseudonymized content item. The output is a ranked queue with reason codes and suggested review steps—not an instruction to publish, delete, redirect, or change a page.

A wrong call wastes review time or leaves a potentially worthwhile page unreviewed. The practical aim is therefore decision support: make the first inspection pass more systematic while keeping final judgment with a person.

The analysis uses the bundled anonymized FlyRank ML Internship starter release. It includes observed search opportunity, freshness, and audience-response signals: impressions, clicks, CTR, average position, content age, update recency, sessions, engagement, scrolling, search volume, competition, CPC, and AI-traffic share.

No client names, domains, URLs, page titles, or raw queries appear in this paper. IDs are used for grouping only, never as features. Label-derived trend fields and recent/previous 30-day performance windows were excluded because they overlap with or define the proxy label.

Methodology

The temporary target is a current-state decline proxy in the starter snapshot; it is not a future post-edit outcome. The transparent baseline ranks eligible pages using log1p(impressions_90d) × (1 + days_since_last_update / 365), requiring at least 500 impressions and 180 days since update.

The logistic-regression model uses 16 non-identifier, non-label-derived snapshot features. Missingness is retained as information rather than blindly converted to zero. Evaluation uses seed 42 and an eight-client grouped holdout: 22,885 rows from 24 clients for training and 7,115 rows from eight unseen clients for testing.

Leakage check: `trend_direction`, `trend_pct`, overlapping 30-day windows, IDs, and decision-derived fields were excluded. An audit run with forbidden `trend_pct` reached ROC AUC 0.999—an implausibly easy result that demonstrates why it must not be used.

At 20 reviews, the model identifies about 17 proxy-positive pages, versus 14 for the baseline. This is an observed improvement in proxy-label ranking, not proof that an edit will cause recovery.

The strongest standardized signals by absolute coefficient were days with impressions, days with sessions, and content age. At a 0.50 threshold, 3,103 of 7,115 test pages were misclassified, reinforcing the need for human context.

Limitations & honest framing

What this does not claim: The proxy label is not a measured future decline or refresh outcome. Results may not generalize beyond this anonymized starter snapshot. The grouped split reduces client memorization but does not replace time-aware or prospective evaluation. Scores show associations here; they do not establish causal drivers, revenue impact, or a search engine’s behavior.

Ranked recommendations

  1. Review the capped queue first. Start with 50 high-visibility candidates, capped at three per pseudonymized client.
  2. Diagnose before editing. Verify analytics coverage, indexing, current search context, intent, seasonality, and content quality.
  3. Separate position opportunities. Use a search-results-page and intent-gap review rather than an automatic refresh.
  4. Record reviewer choices and outcomes. These observations enable a later time-aware evaluation.
  5. Pause when data changes. Revalidate after tracking, site, or template changes; never automate publishing, deletion, redirects, or regulated claims.

The first 50-page queue is estimated at 53.5 hours of first-pass human review. It orders investigation; it is not an automated action list.

Reproducibility

The repository contains the baseline, model, validation audit, action playbook, and capstone notebooks. Install the packages in requirements.txt, run the notebooks in order from Week 1 through the capstone, and use seed 42. Small metrics receipts are retained under work/outputs/; datasets and ranked CSV outputs are deliberately not committed.
